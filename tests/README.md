# 確認の仕組み（tests / tools）

アプリを直したあとに、「壊れていないか」を機械で確かめるための仕組みです。
**プログラムを知らない人が、直接動かす必要はありません**（Claudeなどの作業者が、修正のたびに実行します）。

## 使い方

```
python3 tests/run_all.py           # 静的チェック ＋ 動作テスト（全部）
python3 tests/static_check.py      # 静的チェックだけ（数秒）
python3 tests/e2e_test.py          # 動作テストだけ（ブラウザを自動で動かす）
python3 tools/bump_version.py 2.1.1   # 版の数字を、全部の場所でまとめて更新
```

必要なもの：Python 3、Node.js（文法チェック用）、Playwright（Python版）と Chromium（動作テスト用）。
`pip install playwright` → `playwright install chromium`

## 静的チェック（`static_check.py`）— ファイルの中身を調べる

- `index.html` が読み込むファイルが、すべて存在する
- `sw.js` の保存一覧（FILES）に、必要なファイルがすべて入っていて、存在しないファイルが無い（**書き漏れると、オフラインで動かなくなる**）
- 版の数字が、`js/version.js`・`sw.js`・`index.html`・`README.md`・`CHANGELOG.md` で、そろっている
- JavaScriptの文法が正しい
- 同じ名前の関数・変数が、複数のファイルで二重に定義されていない
- `index.html` の `onclick` などが呼ぶ関数が、すべて定義されている
- `getElementById` で探す id が、`index.html` に存在する
- `js/` の全ファイルが、`index.html` から読み込まれている

## 動作テスト（`e2e_test.py`）— ブラウザで、実際に操作して確かめる

リポジトリのコピー（無いアイコン等は、仮のファイルで補う）を、簡易サーバーで公開し、まっさらなブラウザで操作します。
見た目は、「計算された値」（幅・色・文字の大きさなど）で確かめます。

初期表示／行ごとの枠／色と指示記号の色／クリアとオールクリア／作業名の反映／保存と保存名／保存前の確認／
旧形式のデータの読み込み／QR共有と閲覧モード／旧形式のQR／自動の文字サイズ／選択中のマスの表示／
色の設定／上限／オフライン動作 など。

## 確認できないこと（実機で確かめてください）

- 実際のスマホのカメラで、QRが読み取れるか
- iPhone・Android の実機での、ホーム画面追加・オフライン動作・保存データの扱い（ブラウザとホーム画面のアプリで別になることがある）
- 指での操作のしやすさ、実際の画面の見やすさ（このテストは、計算された値で確かめるため、「見て分かりやすいか」は判断できません）
- 本番（GitHub Pages）に、すべてのファイルが、正しく反映されているか

## テストの足し方

`e2e_test.py` に、`t_名前(br, base)` の関数を追加し、`TESTS` の一覧に入れます。
成功・失敗は、`check('説明', 条件, 失敗時の詳細)` で記録します。**機能を追加・変更したときは、そのテストも、一緒に足してください。**
