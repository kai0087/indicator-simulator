# 指示ビラ・レイアウトシミュレータ

![version](https://img.shields.io/badge/version-2.2.0-blue)
![license](https://img.shields.io/badge/license-MIT-green)

製造ラインの「指示ビラ」（作業の指示を示すマス目の表示）のレイアウトを、スマホやパソコンで作って確認・印刷・共有できるWebアプリです。
インストールは不要で、ブラウザで開いて、ホーム画面に追加すれば、電波が弱い場所でも使えます。

## 使ってみる

**https://kai0087.github.io/indicator-simulator/**

### スマホのホーム画面に追加する

1. 上のアドレスをスマホのブラウザで開く（**最初の1回だけ電波が必要**です）
2. ホーム画面に追加する
   - iPhone（Safari）：共有ボタン → 「ホーム画面に追加」
   - Android（Chrome）：右上のメニュー → 「ホーム画面に追加」（または「アプリをインストール」）
3. 以降はホーム画面のアイコンから開く（電波がなくても開けます）

## できること

| 機能 | 内容 |
| --- | --- |
| 車型タブ | L4 / V6 / GD をワンタップで切り替え。車型ごとに行・列を別々に設定できます |
| 工程名 | 編集画面の「工程名」に入力します。保存名が空のときは、工程名が保存名になります。QRで送ると、受け取った側にも表示されます |
| マス目の設定 | 行（1〜3）と、**行ごとの列数**（各1〜5。例：1行目は3列、2行目は1列）。各行は独立した枠になり、列数が少ない行は、その分だけ短い枠になります（マス1つの幅は、全行で同じです） |
| マスの編集 | 作業名（クリアボタン付き）、指示記号（最大2文字・クリアボタン付き）、背景色（シロ・クロ・アカ・アオ・ミド）と、指示記号の色（自動・アカ・アオ・ミド・キイ）。「自動」では、暗い背景のとき文字が白になります。指示記号の文字サイズは自動で、マスの約60%の大きさになります。選んでいるマスは、黒の太線で囲まれます。マスは左右2分割もできます。作業名は、チェックを入れると他の車型の同じ位置（行・列）にも反映できます |
| 保存・読込 | 1工程ぶん（3車型まとめて）を名前をつけて端末に保存します |
| 保存前の確認 | 「アカ」と書いたのに背景が「アオ」など、文字と背景色が合っていないマスを警告します |
| 色の設定 | 画面上部の「色の設定」で、背景色と指示記号の色それぞれについて、追加・削除・名前や色の変更ができます（各最大20色。端末ごとの設定です。すでに塗ったマスの色は変わりません） |
| オールクリア | 画面上部のボタン。全車型の、工程名・作業名・指示記号（背景色・指示記号の色を含む）をまとめて消します（マスの数と、左右の分割はそのまま。実行前に確認が出ます） |
| QR共有 | 送りたい車型にチェックを入れてQRコードを作ります。相手がスマホのカメラで読み取ると、指示ビラだけが表示されます（閲覧モード） |
| 印刷／PDF | 表示中の車型1枚を印刷またはPDFにできます |

## 基本の使い方

1. 画面上のタブで車型（L4 / V6 / GD）を選ぶ
2. 「行」「列」で、マスの数を決める
3. マスをタップして、右側（スマホでは下側）の編集欄で、作業名・文字・背景色を設定する
4. 工程名をつけて「現在の配置を保存」を押す
5. 他の人に渡すときは「共有/QR」を押して、送りたい車型にチェックを入れ、QRコードを見せる

### QRコードを受け取る側

- スマホの標準カメラでQRコードを読み取り、表示されたアドレスを開きます
- 開くと、**指示ビラだけが表示される「閲覧モード」**になります（編集画面は出ません）。画面の上に、工程名も表示されます
- 複数の車型を受け取ったときは、画面上のタブで切り替えられます
- 受け取った内容を直したい・残したいときは、「編集画面を開く」を押してください。通常の画面に切り替わるので、「現在の配置を保存」で保存できます
- 「アプリが古い可能性があります」と出たら、電波のある場所でアプリを開き直して、最新版にしてください

## 注意事項

- 保存したデータは、**使っている端末のブラウザの中だけ**に残ります。他の端末へは自動では移りません（QR共有を使ってください）
- ブラウザの閲覧データを消すと、保存したレイアウトも消えることがあります
- ブラウザで開いた場合と、ホーム画面のアプリで開いた場合では、保存データが別々になることがあります（特にiPhone）
- QRコードに入れられるデータ量には上限があります。大きすぎるときは、チェックする車型を減らしてください
- このリポジトリは公開されます。**社外秘の情報（実際の工程名・品番など）は、README・設定ファイル・サンプルに書かないでください**
  - 保存したレイアウトは端末の中だけに残り、GitHubには送られません。QRコードのデータも、アドレスの後ろに付くだけで、サーバーには送られません

## 管理者向け：更新のしかた

1. 変更したファイルを、このリポジトリの同じ場所のファイルに上書きします
   - GitHubのリポジトリ画面で「Add file」→「Upload files」→ ファイル（`css`・`js`・`vendor` のフォルダも、フォルダごと）をドラッグ → 「Commit changes」
2. **版の数字を必ず上げてください**（上げないと、端末が古い画面を使い続けます）。`python3 tools/bump_version.py 新しい版` で、`js/version.js`・`sw.js`・`index.html`・`README.md` の版が、まとめて更新されます（手で直す場合は、最低でも `sw.js` の `VERSION`）
3. 数分待つと、GitHub Pagesに反映されます
4. 使う人は、電波のある場所でアプリを開き直すと、新しい版になります（反映に、2回開き直す必要がある場合があります）

> ファイルを追加・削除・名前変更したときは、`sw.js` の `FILES`（オフライン用の保存一覧）も直してください。一覧に無いファイルは、電波がないと読み込めません。また、一覧に書いたファイルが1つでも無いと、オフライン用の保存が失敗します。

### ファイル構成

```
index.html            画面の骨組み
sw.js                 オフライン動作のための裏方（Service Worker）
manifest.webmanifest  ホーム画面に追加するときの名前・色などの設定
icon-192.png / icon-512.png / apple-touch-icon.png   アイコン画像
css/                  見た目
js/                   動き（機能ごとに分けています）
vendor/               他の人が作った部品（QRコード生成）
tests/                確認の仕組み（静的チェック・動作テスト）。tests/README.md を参照
tools/                版の数字を、まとめて更新するツール
```

| ファイル | 役割 |
| --- | --- |
| `css/base.css` | ページ全体の枠組み（色の変数・ヘッダー・ボタン・車型タブ） |
| `css/sheet.css` | 指示ビラ本体の見た目（行の枠・マス・分割の点線・選択の黒枠・自動文字サイズ） |
| `css/panel.css` | 編集パネルの見た目 |
| `css/modal.css` | ポップアップの見た目（保存名・警告・QR共有・色の設定） |
| `css/mode.css` | 閲覧モード（QRを読み取った側）の見た目 |
| `css/print.css` | 印刷・PDFのときの見た目 |
| `js/version.js` | 版の数字（ここが「正」。画面の「ver」表示は、ここから作られます） |
| `js/config.js` | 定数（行・列の上限、初期の色、QR形式の番号など） |
| `js/state.js` | アプリの状態（いま開いている工程・車型・選んでいるマス） |
| `js/data.js` | データの形（1マス・1枚・1工程） |
| `js/colors.js` | 色の一覧、色ボタン、「色の設定」画面 |
| `js/render.js` | ビラを画面に描く |
| `js/layout.js` | 車型タブの切り替え、行・列の設定 |
| `js/editor.js` | マスの編集、作業名、クリア、オールクリア、工程名 |
| `js/presets.js` | 保存・読込・削除、保存前の確認 |
| `js/codec.js` | QRに入れるデータの作り方・読み方 |
| `js/share.js` | QR共有の画面 |
| `js/view.js` | QRを読み取った側の処理（閲覧モード） |
| `js/main.js` | 起動（最初の処理、オフライン用の登録） |
| `vendor/qrcode.js` | QRコード生成ライブラリ（qrcode-generator、MIT） |
| `tests/` | 確認の仕組み（`static_check.py`＝ファイルの中身の検査、`e2e_test.py`＝ブラウザでの動作テスト、`run_all.py`＝全部実行） |
| `tools/bump_version.py` | 版の数字を、全部の場所でまとめて更新 |
| `README.md` / `CHANGELOG.md` | このファイル／変更履歴 |
| `LICENSE` / `THIRD_PARTY_LICENSES.md` | ライセンス／組み込んだライブラリの権利表記 |

> `js` の読み込み順は、`index.html` の `<script>` の並びで決まっています（上から順に読み込まれます）。順番を変えると動かなくなることがあります。

### よくある変更のしかた（開発者向け）

- **車型を増やす**：`js/config.js` の `TYPES` に、名前を足します（例：`['L4', 'V6', 'GD', 'XX']`）。タブ・保存・QR共有・オールクリアが、自動で対応します。最初のマス数を変えたいときは、`DEFAULT_ROWCOLS` にも書きます（書かないと、2行3列）
- **行・列の上限、初期の色、色の名前**：`js/config.js`
- **標準の見た目（色・大きさ・点線）**：`css/` のファイル（ビラ本体は `css/sheet.css`）
- 変更したあとは、版の数字を上げて（`tools/bump_version.py`）、下の確認を実行します

### 修正のあとの確認（開発者向け）

修正のたびに、`python3 tests/run_all.py` を実行して、全部成功することを確認してください（詳しくは `tests/README.md`）。

## 動作環境

- 最近のiPhone（Safari）・Android（Chrome）・パソコンのブラウザ
- 外部のサービスやサーバーには接続しません（すべて端末の中で動きます）
